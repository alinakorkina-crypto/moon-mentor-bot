# Правила работы с Moon Mentor

## Ветки и границы изменений

- Разработку Reading Engine вести только в ветке `codex/reading-engine-v2`.
- Перед началом работы проверять текущую ветку и `git status`.
- Не изменять ветку `main` и не сливать в неё изменения без отдельного разрешения пользователя.
- Не изменять работающего бота, его конфигурацию, процессы и сервер без отдельного разрешения.
- Не выполнять развёртывание, перезапуск серверного бота или другие действия на сервере без отдельного разрешения.
- Сохранять существующие изменения пользователя. Не выполнять разрушительные Git-команды без разрешения.

## Общение с пользователем

- Общаться с пользователем по-русски и объяснять технические результаты простым языком.
- Если требуется действие пользователя, давать один конкретный следующий шаг.
- Команды, проверки и редактирование выполнять самостоятельно в рабочей среде,
  если для этого есть доступ.
- Не перекладывать на пользователя запуск команд в терминале без необходимости.
- После объяснения плана дождаться явного подтверждения пользователя и только
  затем изменять файлы.
- Не создавать коммит, не выполнять push и не открывать pull request без
  отдельного разрешения пользователя.

## Порядок работы

1. Изучить относящийся к задаче код и тесты.
2. До изменения файлов объяснить план: что изменится, зачем и как будет проверено.
3. Выполнить только изменения в согласованном объёме задачи.
4. Запустить соответствующие локальные тесты.
5. Сообщить результат: какие тесты выполнены, сколько прошло, какие ошибки остались.

Не представлять непроверенное поведение как работающее. Если тесты не запускались,
прямо указать это и причину.

## AI-запросы и секреты

- Не выполнять реальные AI-запросы без отдельного разрешения пользователя.
- Запуск preview, вызывающего внешний AI API, также требует разрешения.
- Для локальных тестов использовать подставные AI-функции без сетевых запросов.
- Не добавлять в Git токены, пароли, ключи API, файлы учётных данных и другие секреты.
- Не выводить значения секретов в сообщения, логи и результаты тестов.
- Не включать личные переписки пользователей в код, тестовые данные и документацию.
  Использовать искусственные или обезличенные примеры.

## Целевые требования к Reading Engine

- Один расклад — один AI-запрос. Не добавлять второй запрос для редактирования,
  исправления, повторной генерации или выбора ответа.
- Автоматические повторы транспорта учитывать отдельно: один вызов функции SDK
  сам по себе не гарантирует одну HTTP-попытку.
- Локальная обработка не должна переписывать смысл ответа.
- Допустимая очистка ответа — безопасное удаление Markdown-звёздочек без изменения
  остального текста. Другие преобразования требуют отдельного согласования.
- Валидатор должен сообщать о нарушениях, а не исправлять содержание.
- Диагностические ошибки нельзя скрывать подменой ответа локальным шаблоном.
  Ошибка и отклонённый ответ должны оставаться различимыми для разработчика.
- Не выдавать резервный текст за успешно сгенерированный AI-ответ.
- Карты использовать как символические опоры, а не доказательства фактов,
  будущих событий, мыслей, чувств или мотивов другого человека.
- Не приписывать пользователю чувства, намерения или потребности, которых он
  не называл.
- Не советовать терпеть исчезновения или приспосабливаться к неподходящему формату.
- Сохранять предыдущие экспериментальные версии для сравнения.
  Не удалять и не переписывать их без отдельной задачи.

Эти требования описывают целевое поведение. Наличие отличающегося старого кода
не разрешает воспроизводить его подход в новых изменениях и не означает, что
его нужно автоматически исправлять вне текущей задачи.

## Текущий статус v8

- Reading Engine v8 — эксперимент.
- Он реализован отдельно в `reading_engine_v8.py`.
- OpenAI-транспорт находится в `ai_reader_openai_v8.py`.
- Ручная проверка предусмотрена в `preview_reading_v8.py`.
- Локальные тесты находятся в `test_reading_engine_v8.py`.
- v8 не подключён к `main.py`. Не подключать его без отдельного разрешения.
- v8 возвращает явный `status`: `success`, `rejected`, `error` или `unsupported_route`.
  Готовый `text` есть только при `success`; в остальных случаях он равен `None`.
- Локальная подмена резервным ответом удалена. Доступный отклонённый `final_text`
  сохраняется в `rejected_text` без изменения содержания и форматирования.
- Нормализация применяется только к временной копии для проверки. Успешный ответ
  очищается только от парных Markdown-звёздочек, без обрезания пробелов.
- Штатный OpenAI-транспорт отключает повторы SDK и HTTP-транспорта и не следует
  перенаправлениям. На один запуск расклада допускается не более одной HTTP-попытки.
  Учитываются `HTTPS_PROXY` и `NO_PROXY` из окружения.
  Повторно запускать тот же расклад после ошибки автоматически запрещено.
  Внутреннее поведение внешнего прокси клиент не контролирует.
- `raw_response_text` и `rejected_text` доступны в результате для диагностики,
  но не должны автоматически выводиться в обычные логи или preview.
- Транспорт сохраняет доступные исходный текст, статус API и usage до локальной
  проверки JSON-схемы. Ошибка схемы не должна стирать эти данные.
- Тесты транспорта используют настоящий SDK и считают обращения к подставному
  HTTP-транспорту без интернета.
- Не считать успешные локальные тесты подтверждением качества реальных
  AI-ответов или готовности к развёртыванию.

Техническая история экспериментов: `docs/reading-engine-history.md`.

# История Reading Engine v2–v8

Этот документ нужно обновлять при создании новой версии Reading Engine или
изменении архитектурного решения. Если документация расходится с кодом и
тестами, сначала проверить фактическое состояние и сообщить о расхождении.

Исторические разделы ниже описывают состояние ветки `codex/reading-engine-v2`
на коммите `a6187202d7e9d7ccf3cb02cc6194a3d9dcbe6631`.
Последующие изменения v8 описаны в заключительном разделе.

Причины переходов ниже описывают техническое направление, видимое по коду,
тестам и коммитам. Они не означают, что каждая предыдущая версия была официально
отвергнута или что качество реальных ответов подтверждено сравнительным тестом.

## Общие обозначения

Провайдер указан по соответствующему AI-транспорту и preview.
Сами движки обычно принимают вызываемую AI-функцию.

Число AI-вызовов означает число вызовов на уровне движка. Автоматические повторы
SDK могут увеличивать число HTTP-попыток.

Диапазоны длины указаны в словах. Цель промпта и границы валидатора различаются:
соответствие одному не гарантирует соответствия другому.

## v2 — подробный промпт и проверка качества

Цель:
структурировать расклад через позиции карт, связать ответ с вопросом пользователя
и запрашивать уточнение для явно слишком общего вопроса.

Провайдер:
Google Vertex AI, `gemini-2.5-flash`, через `ai_reader.py`.

AI-вызовы:
один основной; при обнаружении нарушения preview может выполнить ещё один
запрос для исправления. Если требуется уточнение, генерация не выполняется.

Длина:
- карта дня: 100–160;
- личный вопрос, отношения, карьера: 160–260;
- полный расклад: 220–340.

Основные изменения:
- подготовка карт с позициями и тематическими значениями;
- подробные ограничения против чтения мыслей и выдачи символики за факты;
- обнаружение некоторых неподтверждённых утверждений, Markdown и превышения длины;
- отдельный repair-промпт.

Причина следующего эксперимента:
сократить промпт и перейти к готовому ответу за один запрос без AI-редактирования.

Файлы:
`reading_engine_v2.py`, `reading_quality_v2.py`, `preview_reading_v2.py`,
`test_reading_engine_v2.py`, `test_reading_quality_v2.py`.

## v3 / v3.9 — один запрос и минимальная очистка

Цель:
получить цельный короткий ответ без отдельного редактора и без локального
переписывания содержания.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
один, включая случай пустого ответа; повторной генерации нет.

Длина:
- отношения: 110–145;
- карьера и остальные многокарточные расклады: 130–170;
- карта дня: 90–130.

Основные изменения:
- системная инструкция и отдельные тематические профили;
- объединение карт в одну мысль вместо последовательных словарных толкований;
- диагностика длины, структуры и упоминания карт;
- удаление только парных Markdown-звёздочек с сохранением остального текста.

Причина следующего эксперимента:
проверить структурированный JSON как способ явно разделить факты, роли карт
и готовый ответ и сделать результат удобнее для локальной проверки.

Файлы:
`reading_engine_v3.py`, `ai_reader_v3.py`, `preview_reading_v3.py`,
`test_reading_engine_v3.py`.

## v4 — структурированные компоненты ответа

Цель:
получать проверяемый JSON с основаниями разбора и компонентами готового текста.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
один; при ошибке используется локальный резервный ответ.

Длина:
вывод собирается в три абзаца; отдельного числового ограничения слов нет.

Основные изменения:
- JSON-схема и проверки структуры;
- проверка ролей всех карт;
- сборка трёх абзацев в Python из полей ответа;
- локальная подмена результата при ошибках.

Причина следующего эксперимента:
передать модели написание цельного `final_text`, сохранив структурированные
данные для проверки.

Файлы:
`reading_engine_v4.py`, `ai_reader_v4.py`, `preview_reading_v4.py`,
`test_reading_engine_v4.py`.

## v4.1–v4.5 — готовый текст внутри JSON

Цель:
совместить проверяемую структуру с более естественным готовым ответом.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
один. В v4.5 два варианта текста возвращаются в одном ответе модели;
лучший вариант выбирается локально.

Длина:
цель — 110–150; базовая проверка финального текста — 100–170.

Основные изменения:
- v4.1: структурированные основания и цельный `final_text`;
- v4.2: распознавание склонений русских названий карт;
- v4.3: дополнительные ограничения для отношений;
- v4.4: отдельные редакционные профили по типу расклада;
- v4.5: локальная оценка двух вариантов одного AI-ответа.

Причина следующего эксперимента:
проверить разделение анализа и редакторской работы на два последовательных
запроса вместо выполнения обеих задач в одном ответе.

Файлы:
для каждой версии используются соответствующие
`reading_engine_v41.py`–`reading_engine_v45.py`,
`ai_reader_v41.py`–`ai_reader_v45.py`,
`preview_reading_v41.py`–`preview_reading_v45.py`,
`test_reading_engine_v41.py`–`test_reading_engine_v45.py`.

## v5–v5.2 — анализ и редактор

Цель:
сначала получить проверенный структурированный анализ личного вопроса,
затем отдельным запросом превратить его в готовый ответ.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
два при успешном прохождении обоих этапов; при ошибке анализа работа
останавливается после первого вызова.

Длина:
цель — 110–150; проверка — 100–170.

Основные изменения:
- v5: отдельные аналитик и редактор;
- v5.1: более устойчивая обработка JSON и диагностика причин завершения ответа;
- v5.2: движок и проверки v5.1 сохранены, лимит вывода редактора увеличен
  до 4096 токенов.

Причина следующего эксперимента:
явно разделить вопросы об инициативе другого человека и личном выборе,
усилить проверки соответствия вопросу и тематике.

Ограничение относительно текущей цели:
двухэтапная схема не соответствует принципу «один расклад — один AI-запрос».

Файлы:
соответствующие `reading_engine`, `ai_reader`, `preview_reading` и
`test_reading_engine` с суффиксами `v5`, `v51`, `v52`.

## v6 — маршруты и строгая проверка

Цель:
подготовить MVP для вопросов об инициативе и личном выборе с явными маршрутами
и проверками содержания.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
- неподдерживаемый маршрут: 0;
- ошибка анализа: 1;
- полный проход анализа и редактора: 2.

Длина:
цель — 105–140; проверка — 95–150.

Основные изменения:
- определение маршрута вопроса;
- тематические профили;
- структурированный анализ с кодами взаимодействия карт;
- проверки неподтверждённых выводов, смешения тем, пропущенных карт и содержания;
- диагностика транспорта и локальные резервные ответы.

Причина следующего эксперимента:
заменить кодированный анализ содержательным кратким брифом, дать редактору
более естественную основу и отделить стилевые недостатки от опасных ошибок.

Файлы:
`reading_engine_v6.py`, `ai_reader_v6.py`, `preview_reading_v6.py`,
`test_reading_engine_v6.py`.

## v7 / v7.1 — бриф с опорой на вопрос

Цель:
сохранить два этапа, но сделать аналитическую основу содержательнее,
а итоговый язык естественнее.

Провайдер:
Google Vertex AI, `gemini-3.5-flash`.

AI-вызовы:
0–2 в зависимости от маршрута и прохождения анализа.

Длина:
- цель: 130–170;
- стилевое предупреждение: вне 110–190;
- блокирующее отклонение: вне 70–240.

Основные изменения:
- краткий аналитический бриф вместо классификационных кодов;
- привязка вывода к точной цитате из вопроса;
- запрет выдумывать психологическое объяснение;
- разделение блокирующих нарушений и стилевых предупреждений;
- сохранение отклонённого текста для диагностики.

Причина следующего эксперимента:
вернуться к одному запросу, объединив анализ и написание готового ответа
внутри одной модельной операции; отдельно проверить OpenAI-транспорт.

Ограничение:
успешный проход по-прежнему требует двух AI-вызовов.

Файлы:
`reading_engine_v7.py`, `ai_reader_v7.py`, `preview_reading_v7.py`,
`test_reading_engine_v7.py`.

## v8 — один OpenAI-вызов

Цель:
получать готовый ответ одним запросом без отдельного аналитика,
AI-редактора и запроса на исправление.

Провайдер:
OpenAI Responses API.
В коде модель по умолчанию — `gpt-5.6-terra`;
переменная `OPENAI_MODEL` позволяет её переопределить.
Доступность этой модели реальным запросом в данной проверке не подтверждена.

AI-вызовы:
- неподдерживаемый маршрут: 0;
- поддерживаемый маршрут: 1 вызов `model_call`;
- отдельного запроса на исправление нет.

Транспорт создаёт `OpenAI()` без явного отключения автоматических повторов.
Поэтому один вызов движка не гарантирует одну HTTP-попытку.

Длина:
- цель промпта: 110–160;
- стилевое предупреждение: вне 100–175;
- блокирующее отклонение: вне 70–220.

Основные изменения:
- один промпт с вопросом, маршрутом, картами, позициями и допустимыми значениями;
- структурированный ответ с единственным полем `final_text`;
- проверка всех карт и одного завершающего вопроса;
- проверки некоторых опасных утверждений и подмены чужой инициативы
  советом пользователю действовать самому;
- стилевые предупреждения без дополнительного AI-редактирования;
- диагностика модели, статуса и токенов;
- оценка стоимости по таблице цен в коде.

Таблица стоимости — локальная оценка, а не подтверждение актуальных тарифов.

Текущие отличия от целевых требований:
- выполняется нормализация пробелов и переносов строк;
- удаляются Markdown-звёздочки;
- при блокирующей ошибке результат заменяется локальным резервным текстом;
- признаки ошибки доступны через `used_fallback`, `issues`, `stage`
  и, когда он доступен, `rejected_text`.

Ошибки не исчезают из структуры результата, но потребитель, использующий только
поле `text`, может принять резервный текст за успешный AI-ответ. Это требует
отдельного решения до подключения движка.

Статус:
v8 — последняя экспериментальная версия на указанном коммите.
Она не подключена к `main.py`: бот продолжает импортировать `ask_gemini`
из `ai_reader.py`.

Локальные тесты подтверждают проверенные ветви логики с подставными ответами.
Они не подтверждают качество реальных AI-ответов, доступность модели,
работу авторизации или готовность к развёртыванию.

Файлы:
`reading_engine_v8.py`, `ai_reader_openai_v8.py`, `preview_reading_v8.py`,
`test_reading_engine_v8.py`.

## Обновление v8 — явные ошибки и одна HTTP-попытка

Изменения выполнены после базового коммита документации `21040e2` в ветке
`codex/reading-engine-v2`. Они заменяют описанное выше исходное поведение v8
в части подмены ответа, нормализации и повторов транспорта.

Результат движка:
- `success`: готовый `text`, только безопасно удалены парные Markdown-звёздочки;
- `rejected`: ответ не прошёл проверку, `text=None`, причины в `issues`;
- `error`: ошибка вызова, незавершённый ответ или ошибка разбора, `text=None`;
- `unsupported_route`: неподдерживаемый вопрос, `text=None`, ноль вызовов модели.

Локальный резервный текст и поле `used_fallback` удалены из v8.
Доступный отклонённый `final_text` сохраняется в `rejected_text` дословно,
включая Markdown-звёздочки, пробелы и переносы строк. Если извлечь `final_text`
не удалось, `rejected_text=None`. Для валидации используется отдельная
нормализованная копия; исходный текст и payload не изменяются.
Стилевые предупреждения не подменяют и не отклоняют ответ.

OpenAI-транспорт явно задаёт `max_retries=0` и `follow_redirects=False`.
HTTPX создаётся с `trust_env=True` без явного транспорта: это сохраняет
`HTTPS_PROXY`, `ALL_PROXY` и `NO_PROXY`. Стандартные прямой и прокси-транспорты
HTTPX не повторяют подключения по умолчанию. Выполняется один вызов Responses API без повторной
генерации или запасной модели. Клиенты закрываются после запроса.
Вместо печати полного исключения возвращается его тип без сообщения,
которое может содержать чувствительные данные.

Граница гарантии: один запуск движка через штатный OpenAI-транспорт — не более
одной HTTP-попытки. Неподдерживаемый маршрут или ошибка до отправки дают ноль
попыток. Повторный запуск извне и поведение внешнего прокси не контролируются
движком; автоматический повтор расклада после ошибки добавлять нельзя.
`ai_requests` и счётчик preview обозначают вызовы функции модели, а не измерение
HTTP-попыток. Фактические обращения транспорта проверены отдельно тестами.

Файлы проверки:
- `test_reading_engine_v8.py`: контракт результата, сохранение текста и форматирования,
  временная нормализация, предупреждения, ошибки и preview с подставными ответами;
- `test_ai_reader_openai_v8.py`: настоящий OpenAI SDK с `httpx.MockTransport`;
  считаются фактические обращения обработчика HTTP-запросов для успеха, 429, 500,
  тайм-аута, ошибки соединения и перенаправления. В каждом случае — одна попытка.

После изменений кода выполнены целевые тесты и полный набор с заблокированным
`socket.socket.connect`, то есть без доступа в интернет:

    Целевые: Ran 36 tests — OK
    Все:     Ran 268 tests — OK

Исторический результат 255 тестов выше относится к исходному снимку и сохранён
для сравнения. Документация обновлена после успешного прохождения новых проверок.
Реальные AI-запросы не выполнялись. v8 остаётся экспериментом и не подключён
к `main.py`; старые версии v2–v7, сервер и работающий бот не изменялись.


### Исправления после ревью P1/P2

1. Удалена передача явного `HTTPTransport`, которая отключала прокси из окружения.
   Тесты используют настоящий выбор маршрута HTTPX с искусственными `HTTPS_PROXY`
   и `NO_PROXY`, заменяя только создаваемые прямой и прокси-транспорты.
   Счётчики подтверждают одно обращение выбранного транспорта и ноль обращений
   другого: при успехе, 429, 500, тайм-ауте, обрыве соединения и перенаправлении.
   Повтор после ошибки не выполняется. Внутреннее поведение внешнего прокси
   клиент не контролирует.
2. `responses.parse()` заменён одним `responses.create()` со строгой JSON-схемой.
   Доступные исходный `output_text`, статус API, модель и usage сохраняются до
   локальной проверки Pydantic. При ошибке схемы возвращается безопасный код
   `schema_validation_error`, без сообщения исключения и без нового запроса.
3. Разбор JSON v8 использует `json.loads` без нормализации строк. `rejected_text`
   сохраняет значение строкового `final_text` после стандартного декодирования JSON,
   включая неразрывные пробелы, Markdown, CRLF и крайние пробелы. Исходное JSON-
   представление доступно отдельно в `raw_response_text`. Если JSON некорректен,
   исходный текст, статус и usage сохраняются, а `rejected_text=None`.

`raw_response_text` и `rejected_text` не печатаются автоматически ни транспортом,
ни обычным preview. Они доступны только как поля результата для явного разбора
разработчиком. Не следует записывать целый результат в обычные логи.

Итоговая проверка после исправлений, с заблокированной сетью и искусственными
данными:

    Целевые тесты v8: 39 — OK
    Полный набор:   271 — OK

Предыдущие числа 36/268 описывают проверку до исправлений ревью.
Документация обновлена после успешных проверок. Реальные AI-запросы не выполнялись;
`main.py`, v2–v7, сервер и работающий бот не изменялись. Проверка прокси подтверждает
выбор клиентского маршрута, но не доступность внешнего прокси или OpenAI.
